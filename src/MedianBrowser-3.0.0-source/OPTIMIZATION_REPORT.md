# Median Browser 2.1.5 — 全浏览器 KB 级优化报告

本轮以“默认轻量、按需提速、500 KiB 硬预算”为原则，保持现有功能与安全边界不变。

## 2.1.5 主页定制信息架构

个性化主页由 24 行平铺设置改为 7 个功能分区，常用 Logo 页面只显示类型、文字、配色、排版和高级代码；字号、字重、字距与渐变方向再集中到排版子页。设置入口先载入本地主页作为上方预览，修改后只重建轻量本地 HTML，不创建新的 WebView 或第三方 UI 依赖。

自定义 CSS 经过独立纯 Java 校验器：限制 32 KB，拒绝 `</style>`、`@import`、URL、CSS 转义与旧式行为；主页面 CSP 进一步禁止外部连接和子资源。完整 HTML 的 JavaScript 位于无 `allow-same-origin` 的 iframe 沙箱，CSP 禁止 connect，WebView 请求层还会阻止沙箱子框架访问外部 HTTP(S)，只有用户触发的顶层普通导航可离开主页。

## 2.1.4 主页策略与安全 HTML

原先分散的“恢复上次标签”和固定本地主页行为收敛到 `HomeOpenPolicy`：冷启动只在“保留上一次访问的内容”模式恢复会话；本地主页与自定义网页模式都建立单一初始标签。主页键、新建标签、关闭最后标签和完整备份恢复使用同一目标解析，不再出现设置只影响某一个入口的半生效状态。

自定义网页只接受经过现有地址分类器与网络安全解析器验证的 HTTP(S) 地址。自定义 HTML 限制为 64 KB，通过内部资源流按需读取，不写入 APK、不转换成 Base64；渲染层采用无 `allow-scripts`、无 `allow-same-origin` 的 iframe 沙箱，并额外使用 CSP 阻止脚本和外部子资源。用户点击的普通链接可进入正常浏览页，但自定义内容不能获得受信本地主页的内部协议权限。

## 2.1.3 下载进度状态闭环

下载入口现在保留 WebView 已解析的 `contentLength` 并写入任务；真实 GET 响应建立后，以 Content-Range、Content-Length 和受限的常见总长度头校正该提示值。总大小立即进入进程内任务状态、通知和下载中心，普通遥测的零值不再擦除已知值。

进度计算集中到纯 Java 策略并使用浮点比例避免超大文件整数乘法溢出，范围固定为 0–1000。下载中心显示 0.1% 百分比、已下载/总计、速度和剩余时间，进度条轨道加粗；状态上报间隔降至 750 ms，并移除完成状态的重复持久化。未知长度响应保持不确定进度，但会持续显示已下载字节和速度。

## 2.1.2 Logo 排版修复

主页不再写死 `-2.5px` 负字距，改由经过范围校验的配置生成 CSS；内置选择覆盖紧凑、标准及 `+1` 到 `+10 px`。安全标记解析器增加无嵌套的 `[space=0–24]` 自闭合标记，普通空格通过 `white-space: pre-wrap` 保留，因此既可统一调整，也可只扩大某个字符间隙。

渐变方向限制在 `0–360°`，界面提供横向、纵向和对角线常用方向。内置极光、日落、海洋配色重新设计并新增玫瑰金；自定义 2–4 色仍只接受严格 `#RRGGBB`。新增字段完整贯通偏好、主页渲染、备份恢复和重置，解析器与生成 HTML 均有回归测试。

## 2.1.1 安全文字 Logo

文字 Logo 使用独立纯 Java 解析器，仅把白名单 `color` 与 `gradient` 标记转换成经过转义的 span。颜色严格限制为 `#RRGGBB`，渐变限制 2–4 色，禁止嵌套，代码与可见文字分别限制为 1024/48 字符；因此用户可以逐字着色和写渐变，但不能借 Logo 注入 HTML、CSS 属性或 JavaScript。

内置 Median 经典、Google 官方色、极光、日落和海洋预设；自定义编辑器提供语法说明、渐变初始示例和 Google 一键示例。解析器、Google 六色输出、HTML 转义、非法标记和实际主页组合均进入 release 构建测试。

## 2.1.0 个性化主页

个性化数据拆成经过验证的不可变配置和独立图片存储。默认主页不增加图片内存；用户选择图片后，后台将壁纸限制在 2048 像素、Logo 限制在 512 像素，修正常见 EXIF 方向并原子压缩保存。主页只请求 `median.invalid` 下两个固定内部资源，WebView 拦截器仅向受信主页流式返回应用私有文件；不开放文件访问、不生成 Base64 HTML，也不允许普通网页读取。

UI 支持标题、副标题、六种强调色、壁纸遮罩/模糊/适配、两种页面布局、时钟、搜索区显隐与样式、快捷入口列数/形状及一键恢复。配置范围、HTML 转义、资源 URL 和生成脚本均纳入构建自测。

## 2.0.2 菜单触控反馈修复

共享 Action Sheet 的全宽菜单行改用系统有边界波纹，点击状态由行自身裁剪；仅 44 dp 的独立图标按钮保留无边界波纹。静态门禁会阻止全宽菜单行重新引用无边界样式。

## 2.0.1 Omnibox 一致性修复

地址栏、本地首页与隐私模式不再各自猜测输入类型，而是共用 `OmniboxInput`。分类过程不联网、不做 DNS 查询；纯数字、无效 IP、邮箱、含空格文本和普通词语进入搜索，明确 HTTP(S)、有效域名、合法 IP 与 localhost 才进入导航。新增 19 组输入回归用例，release 构建强制执行。

## 2.0.0 全局资源与稳定性

| 子系统 | 1.7.3 风险 | 2.0.0 处理 |
|---|---|---|
| 标签页 UI | 最多 64 张卡片一次性创建 | ListView/BaseAdapter 只创建屏幕所需行并循环复用 |
| WebView 内存 | 固定标签可逃逸热渲染器上限；冷 Bundle 数量无界 | 所有非当前标签均可冻结；按设备保留 1–8 个最近冷状态 |
| 预热/后台 | 多次切换可重复排队预热；备用渲染器可留在后台 | 单一可取消预热任务；onStop 释放备用 WebView，回前台再按需预热 |
| 启动 | 延后任务到点后即使应用已后台仍会编译/联网 | 仅在 Activity resumed 时执行，后台取消、回前台重新排程 |
| 会话与浏览数据 | 相同标签快照仍触发整库序列化，退后台无变化也 flush | 等值快照直接跳过；dirty 写盘只保存真实变化 |
| 脚本 | 相同 URL 重复正则匹配；GM 值反复解析 JSON；安装更新新建线程 | 32 URL 有界匹配缓存、GM 值内存缓存、统一有界空闲线程池 |
| 广告外观规则 | 同一主机重复生成 CSS/过程脚本 | RuleSet 内 24 主机、单项 96 KiB 上限缓存；规则更新天然换代 |
| WebView 安全 | 普通/隐私窗口安全设置重复维护 | `WebViewPolicy` 统一文件、内容、混合内容、Safe Browsing 与 UA 基线 |
| 隐私窗口 | 二次进入、Cookie 回调、后台运行与销毁存在厂商边界问题 | 数据目录只初始化一次；1.5 秒白屏兜底；补齐 pause/resume 与拆除客户端 |
| 下载队列 | 固定线程池等待队列无界 | 最多 48 个等待任务，过载明确失败而不是继续占用内存 |
| 下载持久化 | 每个活动任务约每秒序列化最多 500 条记录 | 5 秒合并遥测写入；暂停、失败、取消、完成立即保存 |
| 下载恢复 | 系统杀掉前台服务后依赖用户手动继续 | `START_REDELIVER_INTENT` 重投原任务，读取已保存游标与校验值恢复 |

最终签名 APK 实测 209,534 字节（约 204.6 KiB），DEX 原始大小 379,552 字节，仍远低于 500 KiB 门禁和用户允许的 800 KB 上限。

## 1.7.3 结构性修复

| 方向 | 原问题 | 修复 |
|---|---|---|
| 请求数 | 每个任务先探测 1 字节再真正下载 | 首个响应直接传输，新任务通常只需一次 GET |
| 临时链接 | 断点复用上次最终 CDN URL | 每次从原始 URL 获取新重定向 |
| 交互 | 暂停只设标记，阻塞读取可等 45 秒 | 控制器持有当前连接并主动断开 |
| Cookie | 重定向响应 Cookie 丢失，跨域 CDN 无登录态 | 逐跳接收 Cookie，并按目标域读取 |
| 索引 | 每秒重新解析并序列化全部下载 JSON | 锁保护进程缓存，只在启动时解析一次 |
| 线程 | 固定池工作线程永久常驻 | 核心线程空闲 30 秒自动回收 |

## 1.7.2 下载可靠性整理

| 方向 | 改动 | 直接收益 |
|---|---|---|
| 功能回退 | 恢复 1.5.1 通用媒体发现，移除 YouTube/SABR 试验解析 | 不再把临时媒体请求伪装成可稳定下载文件 |
| 下载请求 | 每次连接读取目标地址的最新 Cookie；跨源只发送 Origin Referer | 登录态更及时，降低跨站泄露与防盗链失败概率 |
| 重试 | 永久 HTTP 错误快速失败，仅临时错误退避重试 | 403/404 不再无意义重试，网络抖动仍可自动恢复 |
| 去重 | 活动、暂停及刚失败的相同 URL 不再重复建任务 | 避免一次资源堆出多张失败卡片 |
| 恢复 | 队列任务提前注册控制器；进程中断状态自动转暂停 | 排队时也能取消，重启后不会出现永久“下载中” |
| 下载页 | BaseAdapter 回收行、固定按钮槽、只刷新活动任务、批量清理 | 任务列表更平稳，减少对象分配和偏好存储写入 |
| 维护性 | 下载中心状态规则与 HTTP 重试规则拆成纯 Java 策略并自测 | 状态变化可独立验证，减少 UI/网络逻辑互相污染 |

最终签名 APK 实测 180,862 字节（约 176.6 KiB），未使用用户放宽的 800 KB 上限。

## 已实施

| 方向 | 改动 | 直接收益 |
|---|---|---|
| 冷启动 | 过滤规则编译和订阅检查延后到首帧之后 | 避免大规则文件的 I/O、解析与首页渲染争抢 CPU |
| 冷启动 | 过滤订阅、下载索引、离线页索引、朗读、脚本值存储、性能采样和密码库按需初始化 | 未使用功能不再扫描文件、解析偏好、分配采样缓冲或创建执行器 |
| 内存 | 标准模式仅在 512 MB 以上堆设备保留第二个热 WebView | 大多数设备只保留一个渲染器，后台标签冻结恢复 |
| 内存 | 预热 WebView 仅限用户主动选择的性能模式 | 默认模式不再为潜在的新标签支付渲染器成本 |
| 内存 | 脚本、过滤器和密码库线程池空闲 30 秒后回收核心线程 | 用完即退，减少常驻线程栈和调度对象 |
| 请求热路径 | `Accept` 头和请求 URI 只解析一次 | 减少每个子资源请求的重复遍历与对象创建 |
| 请求热路径 | 媒体嗅探先做无分配快速拒绝，识别到媒体后才进入同步区 | 普通图片、脚本、CSS 请求不再争抢媒体索引锁 |
| 广告过滤 | 仅带 `$third-party`/`$~third-party` 的规则计算站点键 | 绝大多数候选规则跳过公共后缀与临时字符串开销 |
| 广告过滤 | 规则去重集合改为线程本地复用；后缀判断移除 varargs 数组 | 降低页面加载期间的短命对象和 GC 压力 |
| 外观过滤 | 先抢占页面注入槽，再生成 CSS/过程规则 | 同页数百个被拦截请求最多生成一次整页规则 |
| 深色模式 | 移除每次调用的反射查找，按 API 级别直接调用 WebSettings | 更少反射、装箱和异常路径，代码也更易审计 |
| APK 体积 | 500 KiB 构建只保留组件构造器，不再强制保留组件全部成员 | 允许 R8 收缩、内联和优化私有实现 |
| 体积门禁 | 签名 APK 大于 512,000 字节时构建直接失败 | 体积预算从提示升级为可执行约束 |
| 可维护性 | 新增 `BrowserServices`，集中管理可选模块的懒加载、内存清理和关闭 | Activity 的可选依赖生命周期有单一入口 |

## 验证门槛

- 所有 53 个 Java 文件必须通过完整 Java 语法解析。
- Android XML、Shell 脚本和项目安全静态规则必须通过。
- 正式交付 APK 必须使用 JDK 17、Android SDK 36 和 Build Tools 构建，并通过项目原有测试、R8、签名、ZIP 完整性检查。
- `tools/build_500kb_apk.sh` 对最终签名 APK 强制执行 512,000 字节上限。

当前环境已完成 JDK 17 + Android SDK 36 编译、R8、签名和 APK 结构验证。由于没有连接 Android 真机或模拟器，冷启动、PSS、页面加载、长时下载和多标签恢复仍是发布前真机硬门槛。
